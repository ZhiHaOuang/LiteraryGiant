# lg-agents

文学专家与任务契约。当前执行选区润色（manuscript-editor / style）、原文证据审阅（critic / continuity），启用规划依赖后支持三方案构思（plot / character / worldbuilding）与场景计划（scene-planner）；chapter-writer 支持已批准计划的空场景起草和当前章节完整正文生成；memory 与 reference 分别接入事实提案和参考分析卡。依赖齐全时共 11 个角色可执行，director 尚未启用。插件配置可禁用专家或补充角色要求。

通过 literaryBooks 读取精确版本与范围，展示完整模型输入；作者确认输入摘要后使用 literaryExecution 执行。润色只能生成选区替换候选；审阅必须给出能定位到原文的证据。两者都不能自动采用正文或确认事实。不调用 Codex 或旧后端。

可选接入 lg-library：任务的 `references` 最多接受 3 个检索引用标识，每条只发送经校验资料的前 1200 字，截断会注明。来源参与预览签名，并在调用前后重新校验；调用中失效不写入候选。引用记录进入候选 metadata，采用前由 lg-books 再校验。没有引用的任务无需安装 lg-library。任务要求最多 2000 字，与候选保存限制一致。

这些校验保证来源和写入边界，不证明模型保留了所有语义。模型仍可能添加动作或情绪判断，必须在编辑台审阅候选。

## 有界规划生成

启用 lg-planning 与 lg-context 后，新增 ideas（三方案构思；PlotAgent / CharacterAgent / WorldbuildingAgent）与 scene-plan（ScenePlannerAgent）。这些规划角色复用同一任务执行入口。作者预览完整输入、材料遗漏、模型与预算，再执行一次有界请求。输出保存为待审方向或待审场景计划，不自动选择、批准或写正文。

ideas 输入 target 为 slug/title/topic/expected_version_id；scene-plan 为 id/expected_token。可带显式 context 与 references，目标卷／章或场景自动绑定来源。执行前后复核目标与材料；无效输出或过期结果保留在任务记录中，不自动修复或重试。重复原操作从规划收据恢复结果，不再次收费；更换任务参数须新预览和新操作。

生成证明由 lg-planning 保存，并在作者选择历史方案或批准计划时重新校验。UI 位于故事规划面板；角色配置仍使用 DSH 插件设置，不另建 Agent 执行循环。

## 规划审阅与反馈改稿

启用 lg-review 后，critic / continuity 支持 plan-review。审阅引用服务提供的句段编号，服务器提取逐字证据并保存版本化报告。ideas / scene-plan 可带 feedback {run, issues:[id]}，只接受同一目标、来源仍有效且尚未处理的问题。完整模型输入显示原方案与所选意见；改稿生成新待审规划，不关闭问题，不自动选择或批准。

## 按批准计划起草

draft-scene 依赖 lg-planning 与 lg-context，只接受当前空场景版本。输入沿用 document/version/token/request/context/references；批准计划、整章快照与材料收据共同绑定一次模型调用。待审替换计划必须先处理，已有正文使用编辑或润色。结果只保存候选；采用前再次校验计划与材料。字数按作品统一规则统计，范围未达标显示提示，不假装模型已经符合要求。不执行整章多场景循环、不自动采用或重试。

## 正文审阅与反馈润色

manuscript-review 使用 lg-review 保存精确版本选区的报告、原文证据与材料收据。polish 可接收 feedback {run, issues}，只接受同一版本和范围中尚未处理的问题。完整预览包括选中的意见，默认沿用审阅材料；即使另选上下文，原审阅依据仍须有效。调用后和采用前复核，问题不会自动关闭。重复报告请求恢复原报告；候选重试复用任务与写入收据。

反馈润色采用 replacement-block-v1：起止独立行 <lg-replacement> / </lg-replacement> 之间仅放替换正文，不要求 JSON 转义或额外说明。解析拒绝缺失／重复边界及边界外解释；不自动修复无效 JSON。其他已有任务的 JSON 契约保持原样。


记忆专家通过 extract-memory 任务接入 lg-memory：只读当前已采纳正文的作者选区，单次生成有编号证据的事实提案，不确认正式记忆。任务可预览、取消及重放；提案保存后重放返回最新处理／过期状态，不再次调用模型。启用支持该接口的 lg-memory 后，memory 角色才标为可执行。

## Reference Agent

启用支持分析卡的 lg-library 后，reference 角色提供 analyze-reference：作者选择 1–3 条原始引用与一个分析类别，预览完整输入和预算，单次生成待审分析卡。重复 operation 读取同一结果；来源变化不保存过期卡片，插件中途停用保留原输出。批准与撤回由 lg-library 的作者界面完成。

## 作者偏好

可选 lg-author 在所有专家准备请求的公共入口加入生效的称呼、详略和按任务适用的写作偏好；完整输入、签名和预算共同覆盖。默认空偏好保持原请求不变。单次 request 与输出/来源契约优先；偏好变化需要重做任务预览。已有候选保留生成时的偏好快照，不因后来修改风格偏好自动失效。

## 整章正文生成

`draft-chapter` 使用 chapter-writer，只接受当前章节正文版本的完整范围（空章为 start=0/end=0）。作者要求、显式上下文和 Library 引用共同进入预览；已有正文也完整发送，超出输入预算直接拒绝，不静默截断。输出必须是完整 replacement，保存为待审候选。

范围是章节文档自身的正文，不自动拼接或覆盖子场景，不替作者选择方向，也不确认正式事实。生成期间来源变化会保留模型结果而阻止写入候选；采用仍经版本与来源校验。lg-workflows 可串接候选审阅及作者选择问题后的改稿。多场景编排与 Director 调度另行迁移。

正文／规划审阅可接收可选 `requirements`（1–2000 字）作为原始创作要求；它与本次审阅 request 分开进入完整输入、预算及请求签名。工作流自动传递已冻结的原始要求。无此字段时保持旧请求格式。

在 DSH「Plugins → lg-agents」详情页可选择文学专家、查看实际已接入的任务、启停专家并修改补充要求。改动通过宿主配置服务保存到当前 profile，对其中各作品生效。已预览但尚未执行的任务在执行前重新核对角色与输入签名。保存面板本身不发起模型请求。多窗口并发编辑使用 DSH 配置修订号检测过期草稿。

candidate-analysis 使用作品监督策略指定的五类专家，逐类为章或场景候选生成证据报告。编辑台可合并预览缺失或过期类别及费用，确认后逐一调用，失败后停止。编号证据由宿主解析为精确文档、版本与原句，报告保存前复核投影快照。有效报告不能重新生成来消除已有冲突。
