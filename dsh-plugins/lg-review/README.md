# 文学审阅记录

作品一致性检查：`literaryReview.consistency(path, {section:'consistency', id}, operation)`，`id: 0` 为全书，其他 ID 为章节／场景及其子场景；HTTP action 为 `consistency`。只读当前章节和场景正文，不扫描未选候选。核对正式事实同键异值、场景计划／字数、约束字面内容、离场人物提及、同时间键事件、全书未回收伏笔；事实与时间线为全局检查。来源未采用／过期／不可用的事实单独提示，不参加当前事实判断。场景字数沿用 lg-books 的混合汉字／英文词计数，和下方纯汉字规则不同。

报告复用审阅表，不覆盖旧报告；记录范围、统计、来源摘要、记录 ID 和原文位置。来源变化标记过期，重试同一 operation 返回原报告；再次检查需新 operation。作者可预览后标记处理／忽略／重开并保存理由，不自动修改正文、正式事实或计划。字面命中不证明违反约束，人物提及可能是回忆，同时间事件可以合理；这里没有模型裁决，也不允许将全书提示直接交给局部改稿。

每类最多 1000 条／400 万序列化字符，正文×约束匹配量最多 2000 万字符，报告最多 100 条提示。超过上限明确失败，不保存残缺的“通过”报告。每条提示最多展示 10 条证据，每段最多 500 UTF-16 字符；正文匹配列第一处。全书未回收伏笔超过 12 条时给规划提醒，该数量不是文学质量标准。界面位于文学编辑台，复用审阅与作者处理面板。

免费正文检查：`literaryReview.check(path, {document, version, token}, rules)`，HTTP 使用 `/api/lg/review` 的 `action: check`。规则可含 `minHan` / `maxHan`（0–400000）、`required` / `forbidden`（每组最多 32 个、每词最多 100 字符）、`ending`（最多 500 字符）。只读所选章节／场景版本全文，不拼接子场景；快照变化拒绝检查。编辑台可填写规则并查看命中位置。

汉字数按 Unicode Han 码点计数，字符数按所有码点计数，段落统计为非空行。词表逐字、区分大小写，允许重叠命中；列出前 20 个 UTF-16 范围并保留完整次数。精确结尾保留末尾空白。返回版本、正文摘要和原规则，不调用模型、不修改数据库、不自动采用；规则与结果仅保留在当前面板，未持久化。没有规则时 `passed: null`。只证明显式规则是否满足，不能判断视角、比喻、逻辑或整体质量；这些仍需审阅。

复用作品 SQLite 的 review_issues，保存模型建议、逐字提取的证据、目标版本和上下文收据。lg-review 负责存储与作者状态；lg-agents 负责有界模型调用；规划面板和正文编辑台复用同一审阅交互。模型不直接关闭问题、选择方案或批准计划。

新审阅保留旧记录，不因模型未发现问题就自动清空其他版本的问题。来源变化时旧报告标记过期，不能作为当前改稿的依据。作者可预览后标记已处理、忽略或重新打开，操作理由和原状态保留在审计表。模型严重度是建议，不是已证实的事实。

逐条校验证据与格式：混合有效／无效条目时保存有效建议，并显示被拒绝条目的序号与原因；全无效则不登记问题。原输出保留在执行账本。方向反馈改稿只允许修改所选问题引用的方案，其他方案由程序保持原样；这不证明模型建议或修订在语义上正确。

正文入口使用 manuscript-review，target 为 section: manuscript、id、version_id、token 和 start/end（JavaScript UTF-16 范围，不允许切开代理对）。报告证据记录绝对字符位置；历史报告保留原版本。勾选问题后将报告绑定的精确选区传给 polish；报告过期、问题已处理或来源改变时拒绝改稿／采用。作者仍可对旧报告记录判断。

章节质量报告通过 quality-preview 只读预览，通过 quality 保存可重放的报告。入口在文学编辑台的当前章正文版本。按实际场景顺序合计章节与已采用的场景卡正文，显示旧版估算字数、非空段数、引号对白占比、章末标记和场景采用数。章末原文保留文档、版本和字符位置。改变来源后旧报告显示过期，作者处理理由保存在历史中。
