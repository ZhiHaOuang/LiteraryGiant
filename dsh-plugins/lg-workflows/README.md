# lg-workflows

将整章生成或选区修订、候选审阅和作者选择问题后的再修订串成可恢复的有界流程。复用 lg-books 的作品 SQLite、lg-agents 专家、lg-review 证据及 lg-execution 累计账本，不引入第二套模型循环。

首次冻结任务类型、正文范围、生成或修订要求、审阅要求、模型/来源签名，以及 2–6 次调用和费用预留上限。每步预览完整模型输入；操作编号固定，重复执行不增加调用。审阅后的改稿只处理作者选择的问题；正文采用和问题裁决仍通过原编辑/审阅面板完成。无文字变化、来源变化、无效结果或达到上限停止后续请求。

工作流表 `lg_workflow_runs` 存于当前作品。运行中断后仅恢复已确定成功的原调用；账本未创建或仍为 reserved 时只能检查，禁止自动重发。停止不回滚已保存的候选和费用。插件停用会取消本实例在途调用。

作者 API `/api/lg/workflows`：preview/create/list/read/next-preview/advance/recover/stop/close。Cordis 服务 `literaryWorkflows`。没有模型可调用的写入工具。

`kind: revision`（默认）从选区 polish 开始；`kind: chapter` 从当前章节完整正文的 draft-chapter 开始，支持空章。后续都审阅生成的精确候选版本，并将原始创作要求单独传入审阅输入和签名，作者选择问题后交给 manuscript-editor 的 polish。整章模式不拼接或修改子场景，也不自动批准规划。

在文学工作流选择「按场景顺序起草」，按起草顺序加入同章已批准计划的空场景。每场调用前可看完整输入、费用和剩余额度。候选可在此预览采用或拒绝，也可到编辑台修改后采用，再刷新流程。拒绝会跳过该场。启用前场引用时，下一场的作者视角上下文会加入前一个已采用场景的摘录，具体范围以预览为准。

API 的 `kind: scenes` 接收章节当前版本和快照 `source`、有序场景 ID 数组 `scenes`、共同的 `request`、`limits`，以及可选的 `carryPrevious`、`context`、`references`。每批 2–6 场。流程创建时校验全部计划，每步重新核对当前场景的批准记录、整章变化和本次输入。已用于后续步骤的前场再次变更时，作者需要复核已有候选。生成结果保存于各场景文档，章节正文仍由作者编辑。已成功付费且候选已落库的步骤可从原收据恢复。

通用任务依赖调度和旧执行任务的原地恢复仍待迁移。

整章生成可选填汉字数、必含词、禁用词和精确结尾。规则与原始创作要求在预览时冻结，每次打开候选或完成改稿后，工作流通过 lg-review 免费检查这一版整章正文。作者可直接勾选失败项，预览由 manuscript-editor 改写该候选的请求，或照常请 critic 审阅。规则改稿占用一次既有调用额度，生成新的候选，正式正文由作者决定是否采用。

场景采用预览会读取作品当前要求的监督报告。作者可查看冲突证据，署名裁决误报，再确认采用。报告变化后须重新预览。流程中的候选可以直接在文学编辑台打开，返回文学工作流时会重新读取原作品、流程和候选。

在「故事规划 → 创作方向」选定方案后，可点「按此方向起草章节」。全书或卷级方向可选择适用章。流程预览、写作与审阅专家会收到该方案的完整内容，保存的候选带有精确来源。重新生成待选方案时，原选择仍然有效。改选、撤回或来源过期后，旧流程停止，旧候选需重新核对方向。

在整章流程中勾选「先生成三个方向，再由我选择」，可分别保存构思、写作和审阅要求。构思专家的一次调用与后续步骤共用次数和费用上限。流程保存三个原始选项及版本；选择预览免费，作者确认后才在作品规划中登记选择。起草前再预览一次。关闭流程会阻止未确认的选择。

「旧版运行历史」按作品读取 RunStore v2 的清单和公开事件。作者预览后可将带摘要的快照存入本书 SQLite。快照保留已完成步骤、旧任务状态与可核对的章节／场景版本；从快照打开版本前会再次核对正文摘要。同一运行的不同公开快照可并存。私有模型事件、工具数据和原始错误诊断不进入快照。

「按章节顺序起草」接收共同要求与 2–6 个章节各自的要求。每章单独预览与生成，作者采用或拒绝后才继续。启用章末衔接时，下一章读取最近已采用章正文结尾的有界摘录，收据绑定整份来源正文和版本。旧预览、未采用候选与拒绝版本不能成为后文的章末依据。生成结果仍由编辑台或工作流中的采用入口独立确认。
