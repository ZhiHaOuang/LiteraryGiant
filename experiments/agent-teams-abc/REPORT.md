# 文学 Agent A/B/C 小样本对照报告

日期：2026-11-11。状态：预定运行结束，助手审读完成，作者独立评阅尚未完成。

**结论：本轮没有证明 C 明显优于 B，不应据此把集群设为标准路径。更准确地说，两道新题的 B 都未交付，因此新题上的 B/C 正文质量差异无法估计。这不是“C 已被证明无效”。**

实验回答了三个较小的问题：直接创作 A 在本批短题中能完成交付；B/C 的结构化中间产物增加了实际失败点；分析、规划和一次统一修订并不能保证最终正文没有状态矛盾。它没有证明文学质量总体改善，也没有验证长篇上下文、故事数据库或日常主 Agent 的自主调度收益。

## 1. 比较的是哪些机制

| 组别 | 执行方式 | 正常请求数/题 |
| --- | --- | ---: |
| A | 同一写作者直接初稿，再统一修订一次 | 2 |
| B | 同一原生会话依次分析、规划、创作，再统一修订一次 | 4 |
| C | 三个原生成员分别分析、规划、创作，以结构化产物交接；写作者在原会话修订 | 4 |

固定 DSH DeepSeek 账号、`deepseek-account/deepseek-flash`、reasoning off；采样沿用供应商默认，没有假设支持 seed。三组的写作提示词、正文约束、修订指令和检查器相同；B/C 的各职责提示词相同。不提供可选方法草稿，不让成员使用任意文件、Shell 或其他工具。每步只开放本职责提交工具。

本轮复用 DSH 原生 `AgentLoop/startActivation`，宿主按固定顺序调度。C 的结果直接交给宿主，不增加模型协调者调用。因此它测试**同会话分阶段与独立成员分阶段的差异**，不是现有主 Agent 自由路由插件的完整端到端消融，不能用这里的成本代表日常 App 成本。

每题只生成一次，失败不重抽。正文 400—600 汉字，标点及 checks 等旁注不计。每组最多8请求、120000 Token保守上限，单请求最多2400输出Token；无HTTP自动重试、无付费裁判。三组上限相同，实际计算量并不相同。

来源为样例书指定的第1、3、4、5章，每题仅拿一章和作者要求，均有版本及SHA256。没有读取全部小说，也没有使用书级已提取资料。前两题校准，后两题在校准结束前未生成；新题与标准事先冻结，不按结果改Prompt。[协议](protocol.json)、[题目清单](case-manifest.json)、[冻结清单](freeze.json)和[数值结果](results.json)可复核。协议中的准备状态保留为冻结时状态，本报告记录执行结果。

## 2. 校准发现的驱动问题

第一次校准 B 消耗8请求，未通过引文校验。驱动把原文段落作为无编号字符串数组提供，模型反复报错段落号；产品上下文原本有显式编号。这属于实验输入缺陷。

修复后，所有组都使用显式段落号；增加离线验证后，以 `v2-` 标签执行整轮比较。原8次及全部失败保留，计入96额度，**排除在文学效果比较之外**。原冻结版本保存在私有 `releases/input-pilot-v1/`。没有改任务或文学提示词，也未把修复前 B 与修复后 A/C 混比。

六组校准结果结束后，核验输入编号、来源摘要、工具限制、会话身份及计量，写入放行记录，再运行新题。A/B使用单会话，C使用三个成员会话。校准后没有继续调整提示词。

## 4. 失败发生在哪一层

| 单元 | 阶段 | 观测 | 本轮处理 |
| --- | --- | --- | --- |
| cal-1 C | 初稿 | `TRANSPORT` | 保留失败，不补跑；低层原因未充分确定 |
| new-1 B | 规划 | 工具JSON出现不合法数组/字段分隔 | 适配器终止，未进入候选校验 |
| new-1 C | 分析 | 工具JSON多一个闭合括号 | 适配器终止，未进入候选校验 |
| new-2 B | 规划 | 工具JSON多一个闭合括号 | 适配器终止，未进入候选校验 |
| new-2 C | 规划 | 合法JSON中多出未许可的 `focus` 字段 | 工具退回错误；模型下次删除该字段，通过后继续 |

后三次JSON失败均为完整工具输出中的语法问题；记录不是 max-tokens 结束。DSH [translate.ts](../../dsh/packages/llm/llm-deepseek/src/translate.ts) 在 `message_stop` 时解析工具参数，失败即终止；本轮这类错误没有进入角色工具的可纠错流程。合法JSON的schema错误则能在原生循环中收到错误结果并修正。它们是两种不同的恢复路径，不能概括成“有校验就会恢复”。

该适配器在JSON校验之后才发出usage，因此三次解析失败没有向本轮账本提供用量；另一次传输失败也缺用量。这不代表供应商没有消耗或收费。相关传输包装在 [adapter.ts](../../dsh/packages/llm/llm-deepseek/src/adapter.ts)。没有据此断言一定是网络、服务端或集群框架本身导致。

## 5. 中间产物是否真正帮助了正文

有可观察的正面行为：cal-2 C的规划强调物品递送、骑士隔在两人之间、接受帮助不等于合作；正文体现了这些约束。new-2 C在侍女在场时改口，保留三天账期；一次schema退回也确实得到修正。

但不足以归因于集群：相同要求A也已收到，而且多数边界同样满足。更关键的反例是：

1. **分析知道，正文仍会写错。** cal-1 B分析已记录手令被扔下、是否拾回未知。初稿却把它放在卧室；修订只把前句改回广场，又在末尾放到城堡门口。一次泛化自检未消除关键矛盾。
2. **引文能匹配，不代表推论成立。** new-2 C的分析摘要把罗兰知道夺位说辞是表演的私有认知，误并入罗兰与巴罗夫的共同认知；原文恰恰写罗兰要让巴罗夫相信它。最终正文未使用这一错误，但中间产物已存在认知污染风险。cal-2 B也把不能保证安全的引文推成不必担心直接受害。
3. **要求少量信息，实际仍膨胀。** 驱动要求3项最相关约束，成功分析却输出3—8项，校验器未强制这个上限。B/C的上下文负担与交接内容并不只由角色人数决定。

因此，本轮能证明的只是某些约束可以被传递和使用；不能证明“结构化分析是正确事实”，更不能证明更多阶段必然让文笔更好。

## 6. 按预定标准作决定

原标准要求两道新题C均不增加严重违例、采用程度均高于B、平均质量至少高1/6且平均Token不超过B的1.5倍，才记录为值得扩大验证的优势信号。

**未达到，也无法完整估计。** new-1 B/C均未交付；new-2 B缺稿。不存在新题B/C的成功配对，不能计算可靠的正文质量增量或完成任务的成本比。不能把缺失稿质量设零，再宣称C赢了；也不能因为C新题失败一次，就宣称多Agent普遍无效。

短题保留A作为后续基线，不把C升级为默认路径；A仍有一致性问题，也没有得到自动采用权限。本轮不修改产品默认行为。

| 顺序 | 只改什么 | 先如何证明有效 |

一次只改变一个机制。暂不加新角色、侧写Agent、长流程或Dashboard功能。修复格式恢复是让文学比较能成立的前提，本身不是文学收益。
